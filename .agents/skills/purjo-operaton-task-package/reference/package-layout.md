|---|---|---|

| `Makefile` | every developer command | no |

## Development environment

Runtime dependencies and the RobotLibrary integration-test dependency live in
`pyproject.toml`. Development tools depend on the selected environment:

- **uv mode**: put `operaton-contracts[templates]`, pytest, pytest-cov, mypy,
  Black, jsonschema, types-jsonschema, and RobotLibrary in the `dev` group;
  run commands as `uv run --group dev make <target>`. RobotCode runs as
  `uv run --group dev --with robotcode==2.7.0 robotcode`, so it sees the
  project's libraries.
- **devenv mode**: put Black, jsonschema, mypy, pytest, pytest-cov, and their
  stubs in `devenv.nix`; keep only RobotLibrary in uv's `dev` group. Set
  `UV_PYTHON` to the devenv interpreter and `PYTHONPATH` to include the project
  root, `.venv` site-packages, and devenv site-packages in that order. Run
  commands as `devenv shell -- make <target>`.

### devenv.nix

Python 3.12 with development tools as Nix packages, `uv` for project
dependencies and Python checks, and RobotCode fetched on demand:

```nix
{ pkgs, ... }:
let
  python = pkgs.python312.withPackages (ps: with ps; [
    black jsonschema mypy pydantic pytest pytest-cov robotframework
    types-jsonschema
  ]);
in
{
  packages = [ python pkgs.uv ];
  env.UV_PYTHON = "${python}/bin/python";
  env.PYTHONPATH = "${toString ./.}:${toString ./.}/.venv/lib/python3.12/site-packages:${python}/lib/python3.12/site-packages";
  scripts.operaton-contracts.exec = ''
    uv run --group dev python -m OperatonContracts "$@"
  '';

  scripts.robotcode.exec = ''
    uv run --group dev --with 'robotcode==2.7.0' robotcode "$@"
  '';
}
```

The devenv and uv environments must use the same Python version. Makefile
targets invoke pytest and mypy from devenv; mypy receives
`--python-executable .venv/bin/python` to resolve the uv-installed project
dependencies. OperatonContracts CLI and Robot commands run through uv.

## Makefile

See [../assets/Makefile.tmpl](../assets/Makefile.tmpl). Conventions:

- `.DEFAULT_GOAL := help`; every public target has a `## description`.
- `WORKSPACE_CMD = cd "$(WORKSPACE_DIR)" &&` so targets work from any cwd and
  `python -m OperatonContracts` resolves the installed package CLI.
- `test`: `OperatonContracts check` → pytest with `--cov-branch
  --cov-fail-under=100` over maintained modules → `robot --dryrun` over all
  task suites → RobotLibrary suites, all with `--output NONE --log NONE
  --report NONE`. Needs no network, Vault, or live API.
- `check`: `uv sync --group dev`, then `black --check` and
  `mypy --strict --explicit-package-bases --python-executable .venv/bin/python`.
- `element-templates`, `check-element-templates` (network: pinned schema).
- `dist: test` then `pur wrap`; `serve`: `pur serve .`;
  `deploy-example*`: `pur operaton deploy <bpmn>`; `clean`. In devenv mode
  also `shell` (`devenv shell`) and `nix-%` (`devenv shell -- $(MAKE) $*`).

## pyproject.toml

```toml
[tool.purjo.topics."<topic>"]
name = "<Robot Task Name>"
on-fail = "ERROR"
process-variables = false     # only task-scope (template-mapped) inputs

[tool.purjo.secrets.default]  # `pur serve .`
provider = "vault"
path = "<path>/<env>-api"
mount-point = "kv"

[tool.purjo.secrets.prod]     # `pur serve --secrets prod .`
provider = "vault"
path = "<path>/production-api"
mount-point = "kv"
```

`on-fail = "ERROR"` turns failures into BPMN errors (the first failure line is
the `errorCode`). Catching them with boundary events needs purjo 1.0rc2 or
newer and suites that set their outputs first; see
[robot-tasks.md](robot-tasks.md#outputs).

Vault keys become Robot variables; declare them as `Secret:` in suites.
Non-secret endpoints come from uppercase environment variables
(`${api_endpoint}    %{PACKAGE_API_ENDPOINT=}`). Serving needs `VAULT_ADDR`
and `VAULT_TOKEN`.

## Ignore files

`.wrapignore` keeps the deployed zip minimal: `AGENTS.md`, `lib/`, `tests/`,
`test_*.robot`, tool caches, `.coverage*`, `.devenv`, `devenv*`, `Makefile`,
`README.md`, `htmlcov/`, `robot.toml`, `secretspec.toml`, `.operaton/`,
`examples/`, `.agents/`, the root template icon, optional `OperatonTemplates.py`,
and large reference specs (OpenAPI).

`.gitignore`: `.venv/`, `.devenv/`, caches, `.coverage*`, `htmlcov/`, `lib/`,
`output.xml`, `log.html`, `report.html`, `robot.zip`, `secrets.json`.

Never commit secrets, `.venv`, Robot outputs, or `robot.zip`.

## Manual runs

`tests/robot_manual_variables.py` (asset `robot_manual_variables.py.tmpl`)
exposes `get_variables()` returning the endpoint as a string and credentials
wrapped in `Secret(...)`, read from environment variables, for
`robot --variablefile tests/robot_manual_variables.py <suite>.robot`.
The installed `OperatonContracts` library imports `OperatonTasks` from the
robot package path, including the suite directory for plain `robot` runs.

## Agent sandbox

When the package runs in a proxied agent-sandbox, allow the schema host in
AGENTS.md's `toml agent-sandbox` block (`*.gitlab.com:443`) plus the Nix and
package-index hosts the devenv needs.
